# 対立的セキュリティレビュー依頼(G4)

あなたはこのローカル HTTP サーバーを破ろうとする攻撃者です。同時に、それを防ぐ側のシニアセキュリティエンジニアでもあります。以下の diff に対し、「動くはず」ではなく「どう壊すか」を具体的な手順で構成してください。

## 脅威モデル

- 攻撃者は被害者と同じマシン上の別プロセス、または被害者にリンクを踏ませられる Web ページ(DNS rebinding / CSRF 的経路)
- サーバーは `127.0.0.1` の localhost。しかしブラウザ経由の攻撃面が残る
- 音声データ・文字起こし結果が外部に漏れることは絶対に許されない

## 具体的に試みること(各々、成立する具体的手順 or 成立しない根拠を述べる)

1. **token バイパス**: token なし / 誤った token / タイミング差 / ログや Referer からの token 漏洩 / SSE クエリ token の露出
2. **DNS rebinding**: Host ヘッダ検証の抜け(大文字小文字、末尾ドット、IPv6 表記 `[::1]`、ポート省略、`localhost` 以外の 127.x.x.x)
3. **CSRF / Origin**: 外部オリジンからの `POST /api/jobs` や cancel が通るか
4. **パストラバーサル**: `/api/download/{id}/{file}` と model 名で `..`、絶対パス、シンボリック、URL エンコード、Unicode 正規化を試す
5. **コマンドインジェクション**: ファイル名・プリセット・モデル名が子プロセス引数やパスに渡る経路
6. **リソース枯渇**: 巨大アップロードでのメモリ / ディスク、多数ジョブ投入、SSE 大量接続、`.partial` の残留
7. **SHA256 検証の回避**: 検証前にファイルが使われる TOCTOU、検証失敗時に `.partial` が残る/使われる

## 出力形式(厳守)

```
## Exploitable
- <file>:<line> — <攻撃名>: <成立する具体手順(リクエスト例含む)> → <影響>

## Not exploitable (checked)
- <攻撃名>: <防がれている根拠(該当コード)>

## Hardening suggestions
- <blocking でないが強化すべき点>
```

Exploitable が 1 件でもあれば blocking として扱われます。憶測ではなく、コードの該当箇所を根拠に述べてください。
