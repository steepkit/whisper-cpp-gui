# Rescue implementation 依頼

先行する実装がこの Issue で行き詰まりました。あなたには、その試みに引きずられず、**白紙から**やり直してほしいのです。失敗した diff は「何がうまくいかなかったか」を理解するために見せますが、同じ設計を踏襲する必要はありません。むしろ別のアプローチを歓迎します。

## 与えられる情報

- Issue 本文と受け入れ条件
- 失敗ブランチの diff(参考。真似る対象ではない)
- 何がうまくいかなかったかの事実記述(症状。原因の断定ではない)

## 進め方

1. まず失敗の症状から、根本原因の仮説を立てる(設計上の問題か、実装バグか、そもそも仕様の矛盾か)
2. 仕様矛盾を疑ったら、実装を進める前に「Questions」で報告する
3. あなたの worktree で、あなたの設計で実装する
4. `implement_issue.md` と同じ完了の定義(受け入れ条件 + 検証 4 コマンド + テスト + 依存追加なし)を満たす

## 出力形式

```
## Root-cause hypothesis
<失敗の原因についてのあなたの見立て>

## My approach (and how it differs)
<採ったアプローチ。前の試みとの違い>

## Summary / Files changed / Acceptance criteria / Verification / Questions
<implement_issue.md と同形式>
```

前の実装者を批判する必要はありません。動くものを、テストで裏付けて出してください。
