# 独立設計案の作成依頼(G0)

あなたはこのリポジトリの独立したシニア Go エンジニアです。以下の課題に対する設計を、白紙から自分で考えてください。**他の誰かが出した設計案はここには含めていません。あなた自身の第一原理からの設計が欲しいのです。** 既存案に寄せる必要はありません。

## 制約(AGENTS.md より、必読)

- Go 標準ライブラリのみ。外部依存なし。ルーティングは `http.ServeMux`(メソッド付き)
- スタブ駆動でテスト可能であること(`testdata/stubs/`)
- レイヤ: server → job → exec の一方向依存。exec は将来 whisper-server 方式へ差し替えられるよう interface 化
- 将来 Tauri sidecar 化を見据え、エンジン + JSON API と静的 SPA を分離

## 出力形式(厳守)

```
## Approach
<設計の骨子。データ構造、状態遷移、主要な型/インターフェース>

## Key decisions & trade-offs
- <判断> : <採用理由> / <捨てた代替> / <リスク>

## Failure modes handled
- <異常系> → <扱い>

## Test strategy
<スタブでどう検証するか。具体的なテストケース>

## Open questions for the human
- <設計を確定する前に人間に確認したい点>
```

実装コードは不要。設計の質(状態遷移の正しさ、異常系の網羅、テスト容易性)で勝負してください。
