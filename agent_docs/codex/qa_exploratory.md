# 探索的 QA 依頼(リリース前)

あなたはこのツールを初めて触る QA エンジニアです。決められたテストケースの消化ではなく、「普通に使ったら壊れそうな所」「開発者が想定していなさそうな操作」を能動的に探してください。この環境に実物の whisper-cli / ffmpeg / macOS はないため、**すべて `testdata/stubs/` のスタブ環境**で行います。

## 探索の切り口(例。ここに縛られず発想を広げてよい)

- 変な入力ファイル: 0 バイト、拡張子詐称、日本語/絵文字/スペース/`..` を含むファイル名、巨大ファイル、ffmpeg が失敗する形式(`STUB_FAIL=1`)
- 操作の順序: 実行中に別ジョブ投入 / 実行中にキャンセル連打 / DL 前にジョブ削除 / モデル未取得のまま開始
- 中断: DL 途中でキャンセル、SSE 接続を途中で切る、サーバー再起動後の状態
- 状態表示: 進捗が stderr パース失敗しても UI が固まらないか、失敗時に stderr 末尾が出るか
- セットアップ導線: バイナリ未発見 / モデル未取得の画面が正しく出るか

## やること

1. スタブ環境でサーバーを起動し(`go run ./cmd/whisper-cpp-gui` 等、必要なら `--port` を使う)、上記を試す
2. 再現手順が確実なものだけを報告する(フレーク疑いは「flaky?」と明記)

## 出力形式

```
## Bugs found
- [severity] <再現手順(番号付き)> → <観測された挙動> / <期待される挙動>

## Rough edges (not bugs but UX 上気になる)
- <点>

## Could not test (実機が要る)
- <スタブでは検証不能だった項目>
```

コードの修正はしないでください(read の範囲で原因の見当がつけば添えてよい)。
