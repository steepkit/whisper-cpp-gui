# ADR

Architecture Decision Records keep durable design decisions separate from the living implementation plan.

## Rules

- Use one file per decision: `NNNN-short-title.md`.
- Do not rewrite accepted ADRs to change history. Add a new ADR that supersedes the old one.
- Status values: `Accepted`, `Superseded`, `Deprecated`.
- Keep ADRs short: context, decision, consequences, and superseded-by when applicable.
- `docs/implementation_plan.md` remains the current specification. ADRs explain why stable decisions were made.
